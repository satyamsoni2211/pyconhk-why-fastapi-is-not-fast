The call that freezes everyone

Blocking the event loop
5:00–9:00. The single most common killer, and the hardest to catch in code review.

Looks async. Isn't.

BAD 
@router.get("/bad")
async def blocking_call():
    resp = requests.get(
        f"{GATEWAY_URL}/delay/1",
        timeout=10,
    )  # sync call inside async def
    return {"gateway_status": resp.status_code}

async def on the outside…

requests.get() never yields.

The whole loop freezes — not just this request.

The Orders API calls an external payment gateway before confirming an order — classic slow I/O. async def, but requests.get() is synchronous: it blocks the ENTIRE event loop, not just this request. Code highlight steps with each click: async def → the sync call → the return.

Rebuilding the world on every request

Dependency injection lifecycle
9:00–13:00. Misconfigured DI that looks clean but re-initializes heavyweight objects on every request.

New engine. New pool. Every request.

BAD 
async def get_bad_db_session():
    engine = build_engine(get_settings())
    async with build_sessionmaker(engine)() as s:
        yield s
    await engine.dispose()

Fresh engine.

Fresh pool.

Fresh TCP handshake.

Every. Single. Request.

Depends() is powerful, but nothing stops you building a brand-new engine or HTTP client INSIDE the dependency, on every request.

The fix: build once, borrow forever

GOOD 
@asynccontextmanager
async def lifespan(app: FastAPI):
    engine = build_engine(get_settings())
    app.state.sessionmaker = \
        build_sessionmaker(engine)
    app.state.http_client = httpx.AsyncClient()
    yield
    await app.state.http_client.aclose()
    await engine.dispose()

async def get_session(request: Request):
    async with request.app.state.sessionmaker() as s:
        yield s

Build once in the lifespan.

Clean up on shutdown.

ANTI-PATTERN 4 OF 5

Validating the same data twice

Pydantic validation overhead
17:00–21:00. The one most people recognize from their own codebase.

Validate it twice, pay for it twice

BAD 
def bad_transform(order) -> dict:
    raw = {"id": str(order.id), ...}  # manual dict
    v = BadOrder.model_validate(raw)
    d = v.model_dump()                # round-trip 1
    r = BadOrder.model_validate(d)    # round-trip 2
    return r.model_dump()

Nested models + validator chains + one sneaky dump → validate round-trip.

Redundant model_dump -> model_validate round-trip: common in middleware/serializer layers that grew organically. "Oh, we have that" is the usual reaction.

Same data. ~1.9× slower.

The fix: validate once, from the source

GOOD 
class GoodOrder(BaseModel):
    model_config = ConfigDict(from_attributes=True)
    id: uuid.UUID
    items: list[GoodOrderItem]

def good_transform(order) -> dict:
    return GoodOrder.model_validate(order) \
        .model_dump(mode="json")
  • from_attributes=True — read straight from the ORM object.
  • Data never leaves the process? Skip Pydantic. A dataclass will do.
from_attributes=True, and the point people forget: skip Pydantic entirely for internal-only data.
